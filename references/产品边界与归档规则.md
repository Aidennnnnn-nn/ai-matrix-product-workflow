# 产品边界与归档规则

## 规则优先级

1. 用户最新确认。
2. 当前项目的 `AGENTS.md` 和全局规则文件。
3. 本参考中的便携基线。
4. 历史材料与推断。

发生冲突时不得静默合并，应采用更高优先级规则，并在必要时说明差异。

## 产品结构

AI MATRIX 按“底座 -> 中台 -> 前台 -> 用户”的支撑关系表达：

- 数智管理基座：统一用户、企业组织、角色、权限、下载、消息和多语言能力。
- AI数据中台：数据资产、IoT / 物联、物模型、指标和数据治理能力。
- AI服务中台（AI Service Center）：Skill、标注、MCP、监控治理和 AI 能力交付。
- AI运维平台：面向售后、售前、研发等内部用户的业务前台。
- SEMS+ APP/WEB 与开发者平台 / OpenAPI：其他业务前台，由底座和中台能力支撑。

SEMS+ 的独立需求保留在对应全局或自身项目范围，不因 AI MATRIX 需求拆解而强行归入某个中台。

## 默认目录

以下路径均相对于项目根目录：

```text
docs/中台架构/
├── 10_需求调研/
├── 20_项目材料/
├── 40_产品架构/
└── 50_需求文档/
    ├── 01_AI运维中台/       # 展示名：AI运维平台
    ├── 02_AI数据中台/
    ├── 03_AI服务中台/
    ├── 04_数智管理基座/
    └── 全局规则/
```

归档判断：

| 材料 | 默认归属 |
|---|---|
| 产品族、边界、角色权限、对象模型、跨系统流程 | `40_产品架构/` |
| 需求调研 | `10_需求调研/` |
| AI 技术调研 | `10_需求调研/AI技术调研/`，用 `Agent_`、`Skill_`、`MCP_` 等文件名前缀区分 |
| AI运维平台需求 | `50_需求文档/01_AI运维中台/` |
| AI数据中台需求 | `50_需求文档/02_AI数据中台/` |
| AI服务中台需求 | `50_需求文档/03_AI服务中台/` |
| 数智管理基座需求 | `50_需求文档/04_数智管理基座/` |
| 跨平台通用规则 | `50_需求文档/全局规则/` |

## 特殊归属

- MCP 管理属于 AI服务中台，通常归入 `03_AI服务中台/MCP中心/`。
- IoT 不作为独立同级平台。设备接入、协议适配、Packet 数据、遥测采集、设备控制、物模型、控制定义、能力识别和数据质量默认归入 AI数据中台。
- 无法归属于单一功能的跨功能需求，按平台和批次归入 `需求池/<版本>/`。目录版本表示需求批次，文件版本表示文档或原型自身修订版本。

## 文件夹控制

- 菜单层级、功能规划和研发阶段不自动等同于文件夹。
- 尚未产出材料的功能保留在需求清单或需求总表中，不预建空目录。
- 单个功能只有少量材料时，优先放在最接近的业务目录。
- 不批量创建“需求分析、需求池、流程、实体建模、技术方案、测试用例、发布记录”等开发阶段空目录。
- 只有材料数量和长期维护需求明确时，才增加下级目录。

## 命名与同步

- 面向用户阅读、汇报和归档的文件优先使用清晰中文命名。
- 保留必要的 `API`、`JSON`、`CSV`、`MCP`、版本号和日期。
- 推荐文件名结构：`主题_用途_版本或日期`。
- 调整目录规划、产品边界或归档规则时，同步更新项目 `AGENTS.md`、全局归档规则和旧路径引用。

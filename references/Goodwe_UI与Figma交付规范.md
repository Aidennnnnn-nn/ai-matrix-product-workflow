# Goodwe UI 与 Figma 交付规范

## 证据优先级

1. 用户最新确认。
2. 当前 AI MATRIX 项目级 UI 规范。
3. 已确认的设计系统组件和 Token。
4. Goodwe 登录框架与运维平台的页面组合模式。
5. 明确标注的阶段性决定或待确认内容。

页面截图只用于理解组合、密度和层级，不得覆盖已确认组件规格，也不得作为实现层。

## 默认业务后台基线

- 主题：Light。
- 设计视口：`1440 x 900px`。
- 顶部栏：`48px`。
- 折叠侧栏：`60px`。
- 工作区背景：`#F8F8F8`。
- 品牌红：`#FF323A`。
- 字体优先使用 `Poppins`，中文使用项目确认的系统回退字体。
- Web Radio / Checkbox 默认 `16 x 16px`。

登录页控件与业务后台控件必须分开。登录场景中的大尺寸 Radio 或主题切换规格不得直接外推到后台页面。

## HTML 原型要求

- 先读取项目级 UI 规范和相关设计证据，再开始页面设计。
- 使用稳定尺寸、响应式约束和清晰的信息层级。
- 图标按钮使用项目图标库或已确认组件，不手绘替代已有图标。
- 页面文字不得溢出、遮挡或挤压相邻控件。
- 工具型页面保持安静、紧凑和便于扫描，不使用营销式大 Hero 或装饰性卡片堆叠。
- 主流程和自然需要的控件、弹层、空态、反馈状态必须可操作。
- 用户针对 HTML 的批注先落回 HTML 事实源，确认后才同步 Figma。

## Figma 前置读取

每次新建原型前，通过 Figma 官方 MCP：

1. 读取目标文件和目标页面的元数据。
2. 定位与当前页面最相关的 Frame、组件和变量。
3. 获取设计上下文和截图。
4. 记录实际采用的设计证据，不根据截图猜测未提供的组件状态。

目标 Figma 文件必须来自当前项目配置或用户当次明确确认。便携 Skill 不硬编码任何个人或组织的文件 URL。

## 页面和 Frame 命名

新建页面使用：

```text
【系统名称】【一级目录】【二级菜单】
```

示例：

```text
【数智管理基座】【权限管理】【AI能力权限管理】
```

层级不明确时先确认，不使用 `Page 1`、`其他`、`默认`等占位名交付。根 Frame 名应能表达页面和状态，避免无意义编号。

## 写入约束

- HTML 经明确确认后才写入。
- 使用 Figma 官方 MCP 和当前环境中适用的 Figma Skill。
- 页面、区块、文本、按钮、图形和组件保持原生可编辑。
- 优先复用已有组件、变量和样式；复用失败时说明原因，再建立最小必要结构。
- 新建顶层 Frame 避开既有内容，除非用户明确要求覆盖指定节点。
- 不使用浏览器点击、剪贴板导入或单张整页位图作为交付链路。

## 回读验收

写入后必须：

1. 获取根 Frame 截图，检查空白、重叠、裁切、字体、颜色和主要间距。
2. 回读根 Frame 尺寸、子层级、关键文本和节点数量。
3. 核对页面名、Frame 名、关键状态、需求编号和交互表达。
4. 对问题读取实际节点属性后定点修复，修复后重新截图。
5. 交付带节点标识的链接，并说明与 HTML 基线是否存在差异。

## 公开分享边界

- 不把内部 Figma URL、飞书链接、账号、人员信息或本机绝对路径写入公共仓库。
- 示例使用占位地址和相对路径。
- 若项目内部规则与公共 Skill 不一致，以内部当前规则为准。
